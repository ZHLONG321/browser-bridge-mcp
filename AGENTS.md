# Browser Bridge MCP

This repository owns the standalone browser extensions, loopback HTTP service, MCP stdio adapter, clients, Windows native guards and browser-bridge skill. Node.js and Python implement the same HTTP service protocol. The MCP adapter uses the official SDK and delegates to the Node client and existing guarded helpers; do not duplicate browser operations or change extension wire contracts in that adapter. Its entry point is `skills/browser-bridge/scripts/mcp/server.mjs`. Keep stdout reserved for MCP messages and use stderr for diagnostics. The shared HTTP service starts only through its explicit start tool and survives MCP disconnects.

MCP tools use explicit resource/action names, with Chromium and Firefox prefixes for protocol-specific operations. Each fixed action has its own tool and action-specific schema; the adapter supplies the existing HTTP action internally. Keep profile/privacy/window selection explicit and preserve raw JavaScript, CDP and native API/packet capabilities. Tool names and their mapping belong in `skills/browser-bridge/references/mcp.md`; client functions and the HTTP protocol retain their existing names.

Keep profile and privacy selection explicit on every browser call. Resolve all user-supplied target conditions against live candidates. Preserve window constraints and ask about ambiguity rather than selecting the first match. Do not introduce persistent current/default target state.

Discover available browsers before asking the user to choose. A single available browser or a target uniquely resolved from the user's conditions is sufficient for automatic selection. Distinguish Chromium browser products using process identity or candidate-page metadata when needed. Multiple profiles of one browser require target resolution, not another browser-choice prompt.

Background-only operations must not activate tabs, focus or minimize windows, or send desktop input. Windows native guard source and bundled x64 DLLs belong together; rebuild the affected DLL when changing its source. Refer to `skills/browser-bridge/references/windows.md` for the compiler commands and activation guards.

Chromium `debugging` supports read-only status and an authorized enable operation for an exact tab. Both server runtimes validate the same target, privacy, window and mutation contracts. The saved profile-wide enabled preference is separate from actual owned attachments. UI connection labels use live target checks, not the preference alone. A manual off/banner cancellation stops reconnection; enabling through a later authorized task is explicit. See `skills/browser-bridge/references/operations.md` for result and failure semantics.

Core servers and clients use standard libraries. Optional Windows Edge profile association uses the pinned dependency documented in `skills/browser-bridge/references/setup.md`. Keep browser profiles, credentials, connection state and generated artifacts out of Git. Temporary work belongs in `tmp/<session-id>/`.

The installed browser-bridge skill is a separate copy from this checkout. Repository changes do not automatically update an installed skill, reload extensions or restart a running service. Explain the applicable reload or installation step when changing those components.

The HTTP service is shared across clients and Codex sessions. Reuse it rather than restarting it per session. Node shutdown must close active long polls after acknowledging the stop; closing the listener alone can leave extensions polling a retired process. Snapshot authentication failures must invalidate only the matching Chromium transport, preserving dispatched jobs/results. Empty discovery during reconnection requires bounded read-only rechecks before requesting an extension reload; see the setup reference.

The sole installable skill lives in `skills/browser-bridge/`, including its extensions, scripts, references and locked MCP dependencies. Keep that directory self-contained and preserve internal relative paths. The root README is the installation entry point: a request containing only the repository URL must let an installing agent discover the skill, install its MCP dependencies and register it in the current client without asking for a skill path or name. Follow `skills/browser-bridge/references/mcp.md` and compute executable/entry paths on the installation machine. Run documented skill commands from that directory.
